# Копирование инстанса AmneziaWG

Короткая инструкция: что делает кнопка **«Копировать инстанс»**, что при этом
меняется у пользователей и как проверить результат.

---

## 1. Что переносится, а что нет

Копируется состояние контейнера **как есть**:

- все пиры (`[Peer]`-блоки), включая отключённые;
- серверный ключ, приватные ключи пиров, `PresharedKey`;
- `clientsTable`, `multi_ip.json`, `conn_warnings.json`;
- параметры обфускации (`Jc`, `Jmin`, `Jmax`, `H1..H4`, `I1..I5`), `MTU`, `DNS`;
- обвязка привязок «пир → пользователь» в панели.

Меняется только техническая обвязка:

| Что | Источник | Цель |
|---|---|---|
| ключ инстанса в панели | `awg3` | `awg3__6` (следующий свободный) |
| имя контейнера | `amnezia-awg3` | `amnezia-awg3-6` |
| `ListenPort` в `awg0.conf` | 55424 | свободный порт на цели |

**Не переносится:**

- публичный адрес (`public_host` / `public_port`) — настраивается отдельно
  в «Публичный адрес» на целевом сервере;
- счётчики трафика пользователей — у копий они начинаются с нуля
  (`created_at` и имя привязки сохраняются);
- старые `awg0.conf.bak.*`, каталог `warp` и `warp-link-*`;
- сервер не останавливается и не изменяется — источник остаётся как был.

> Копия использует **тот же серверный ключ**. Поэтому старые конфиги
> пользователей продолжают работать и через источник, и через копию.
> Пока пользователь не сменил endpoint, он подключается к источнику.

---

## 2. Как скопировать

1. Открыть карточку сервера → карточку AmneziaWG-инстанса.
2. Нажать **«Копировать инстанс»**.
3. В модалке выбрать **целевой сервер** (свой сервер в списке отсутствует).
4. Дождаться предпросмотра: имя копии, порт, число пиров, предупреждения:
   - *«Порт N занят, будет использован M»* — норма, endpoint потом указывать `M`;
   - *«Сначала будет перенесён docker-образ»* — на цели нет образа, это дольше.
5. Нажать **«Копировать»**. Идёт шкала с процентами и журналом по шагам.
6. По завершении — имя нового инстанса и число скопированных привязок.

Ограничения:

- только AmneziaWG 2.0 / 3.1 (`awg`, `awg2`, `awg3`), не `awg_legacy`;
- только на **другой** сервер;
- **по одному инстансу за раз** на всю панель (вторая попытка получит
  `copy_in_progress`);
- «Отмена» = полный откат: созданный на цели контейнер удаляется.

Если копирование упало на любом шаге, панель сама удаляет созданный контейнер
и не пишет инстанс в `data.json`. Если удалить не удалось, в журнале будет
явный текст «контейнер X мог остаться, проверь вручную».

---

## 3. Что делать пользователям: поменять только endpoint

Ключи, PSK, `AllowedIPs` и параметры обфускации остаются прежними — их менять
**нельзя**, иначе подключение сломается. Меняется одна строка в конфиге.

Было:

```ini
[Peer]
Endpoint = lamanama.duckdns.org:60002
```

Стало:

```ini
[Peer]
Endpoint = 104.128.137.107:55551
```

Порядок действий:

1. Администратор: на целевом сервере открыть инстанс → **«Публичный адрес»**,
   если пользователи ходят через домен/DNAT. Без этого в конфиг попадает
   прямой `host:port` сервера.
2. Пользователь: в приложении Amnezia открыть конфигурацию → **Endpoint** →
   заменить `host:port` на новый. Либо отредактировать файл конфига/QR и
   переимпортировать его.
3. Остальные строки (`PrivateKey`, `PublicKey`, `PresharedKey`, `AllowedIPs`,
   `Jc`, `Jmin`, `Jmax`, `H1..H4`, `I1..I5`) — **не трогать**.

Формула нового значения: `<host или публичный домен>:<порт копии>`.
Порт копии показан в модалке до запуска и в карточке инстанса после.

---

## 4. Проверка после копирования

На целевом сервере:

```bash
docker ps --format '{{.Names}}\t{{.Status}}\t{{.Ports}}' | grep amnezia-awg
docker exec amnezia-awg3-6 awg show awg0 | grep -c '^peer:'      # = пиров на источнике
docker exec amnezia-awg3-6 grep -E '^(Address|ListenPort)' /opt/amnezia/awg/awg0.conf
ss -lun | grep ':55424 '
```

В панели: карточка целевого сервера → инстанс показывает «запущен», порт и
число подключений; в карточках пользователей появились привязки к новому
инстансу.

На источнике: ничего не изменилось, контейнер и пиры на месте.

---

## 5. Если что-то не так

| Сообщение | Что значит | Что делать |
|---|---|---|
| `Порт N занят на цели; будет использован M` | порт источника занят | endpoint указывать `M` |
| `Source container is stopped` | контейнер-источник остановлен | поднять контейнер источника |
| `A container named ... already exists` | на цели есть контейнер вне панели | убрать или переименовать его |
| `The target tunnel did not come up` | старые `awg`-tools или нет модуля | фича сначала сама копирует бинарники; если повтор — проверить модуль AmneziaWG на цели |
| `No free UDP port on the target` | занят весь диапазон | освободить порт вручную |
| `Another instance copy is already running` | идёт другая копия | дождаться завершения |

## 6. Текущий пример: NATA → MAMKAM

| Инстанс | Было (NATA) | Копия (MAMKAM) | Endpoint для пользователей |
|---|---|---|---|
| awg2 | `lamanama.duckdns.org:60002` (внутри 55551) | `amnezia-awg2`, порт 55551 | `104.128.137.107:55551` |
| awg3 | `lamanama.duckdns.org:60001` (внутри 55424) | `amnezia-awg3-5`, порт 55424 | `104.128.137.107:55424` |

Пользователям достаточно заменить строку `Endpoint` целиком на
`104.128.137.107:<порт из таблицы>` — остальное в конфиге не меняется.
Домен `lamanama.duckdns.org` указывает на NATA, поэтому для копий его
использовать нельзя, пока владелец не переключит DNS или не настроит
публичный адрес и DNAT на MAMKAM.
